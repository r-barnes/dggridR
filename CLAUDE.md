## Package Overview

dggridR is an R package providing Discrete Global Grids (DGGs) — spatial binning using equal-area hexagonal, triangular, and diamond cells across Earth's surface. It bridges R to the DGGRID C++ engine via Rcpp.

## Architecture

The package has three tiers:

**R API** (`R/dggridR.R`) — User-facing functions: `dgconstruct()` builds a grid spec, `dgcellstogrid()` / `dgearthgrid()` / `dgrectgrid()` materialize cells as sf geometries, `dg_closest_res_*()` selects resolution by target area/spacing.

**Rcpp Bridge** (`copy_to_src/`) — The hand-written C++ bridge that must not be overwritten by `update_from_upstream.sh`:
- `dglib.h` / `dglib.cpp` — `Transformer`, `GlobalGridGenerator`, `SeqNumGridGenerator` classes that wrap the DGGRID engine
- `Rwrapper.cpp` — `RCPP_MODULE` declarations exposing C++ to R
- `cgen_head.h`, `cgen_body.h`, `cgen_funcs.h` — **auto-generated** by `func_gen.py`; do not edit by hand
- `func_gen.py` — Generates the 30 coordinate-conversion functions (5 input types × 6 output types)

**DGGRID Engine** (`src/`) — Vendored C++ library. **Entirely auto-generated** by `update_from_upstream.sh` from `submodules/DGGRID`. Never edit files under `src/` directly; changes will be overwritten. The submodule lives at `submodules/DGGRID` and tracks `https://github.com/r-barnes/DGGRID.git`.

## Coordinate Systems

The 30 generated functions (`R/cwrapper.R`) convert between:
- **GEO** — geographic (lon_deg, lat_deg)
- **SEQNUM** — globally unique integer cell ID (most commonly used)
- **Q2DI** / **Q2DD** — quad-based integer/double coordinates
- **PROJTRI** — projected triangle
- **PLANE** — planar (output only)

`dgGEO_to_SEQNUM()` and `dgSEQNUM_to_GEO()` are the most commonly used.

## Key Design Decisions

- `src/` is regenerable — `update_from_upstream.sh` handles all patching (flattening include paths, renaming `.hpp` → `_hpp.h` for CRAN, removing `M_2PI` to avoid R header collision).
- `copy_to_src/` holds the non-generated bridge code. After any upstream update, `update_from_upstream.sh` copies files from `copy_to_src/` into `src/` as its final step.
- The Apple Silicon numeric precision fix lives in `copy_to_src/dglib.cpp` and must survive submodule updates.
- `R/cwrapper.R` is auto-generated by `func_gen.py` — do not edit it by hand.
- Dependencies were intentionally minimized in v3.1.0: dplyr/rlang/sp replaced by collapse/s2.

## Updating DGGRID

See `UPDATE_DGGRID.md` for the full 8-phase process. Key fragile points:
1. `DgIDGGSBase::makeRF()` signature — any upstream parameter change silently breaks compilation
2. New `.cpp` files upstream — `update_from_upstream.sh` only copies known directories; new files need manual additions
3. Header include regex fixes in `update_from_upstream.sh` are brittle and may need updating
